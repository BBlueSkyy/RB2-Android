# Raging Blast 2 on Android - progress log

Target: AYN Thor (Snapdragon 8 Gen 2 / Adreno 740, Android 13). Owner tests, Claude builds.
Approach: reuse the Project8Recomp (THP8) Android port wholesale - same patched ReXGlue SDK
(v0.10.0 + the THP8 patch stack, copied here as patches/rexglue-sdk-android 0001-0035), same Android shell (SDL GameActivity, launcher, in-game menu, Turnip
driver bundle, frame pacing / frame generation, test scripts) - and swap in this game's code.

No game content is ever committed: no disc image, `default.xex`, extracted files or generated code.

## Sources

- Game code: this repo, forked from WistfulHopes/RB2 ("Dragon Ball Raging Blast 2 Recompiled",
  BSD-3-Clause, last upstream commit 2026-02-21). Branch `android`.
- Disc: the tester's own dump (USA Rev 1), extracted with tools/android/xdvdfs.py (XGD2 partition at
  0xFD90000; title 4E4D0826, media 45ACA4A0, default.xex 7,151,616 bytes,
  SHA-1 F57B501FA2CDD309C2C56B76A5F297ACBC564FD2).

## Session 1 (2026-10-11): first Android build

- Upstream code targets the pre-0.2 SDK. Migration to SDK 0.10:
  - Its hand-written heap (dlmalloc arena over RtlAllocateHeap & co.) and file I/O hooks
    (src/bdengine) are what the SDK now ships as `rexcrt`; the manifest maps the game's routines in
    `[entrypoint.rexcrt]` (heap, file I/O, memcpy/memset/memmove, strncmp/strncpy/strcpy_s/wcslen),
    which also switches the SDK's native heap on (REXCRT_HEAP).
  - The 19 import stubs are all implemented by SDK 0.10: dropped.
  - printf-family hooks dropped (they handed guest va_lists to the host CRT - only worked on MSVC).
  - Kept: SpGameServer::_vsyncWait (sub_8249B680) replaced by a sleep to the next 60 Hz boundary
    (src/rb2_hooks.h; cvars rb2_vsync_timer, rb2_vsync_hz).
- Manifest: config/rb2_manifest.toml, generated by tools/android/mkmanifest.py from the upstream
  rb2_config.toml (11,882 functions). One extra function (0x822289C8-0x82228C78, a 5-way switch
  tail-jumped from sub_82228350) - without it SDK 0.10 left 12 unresolved branches (REX_FATAL).
- Codegen: 3.8 s, 91 files (tools/android/codegen.sh <extracted disc>).
- Android shell copied from Project8Recomp `android/` (package org.rb2recomp.android, app name
  "Raging Blast 2"); THP8-only hooks removed (guest_resolution / guest_present_interval /
  guest_wait_sleep). LaunchConfig keeps only SDK-level settings; default frame-rate mode = 60.
- First device runs (rb2-a1): boots on Turnip, 60 fps / 50 draws of black for exactly 300 frames,
  then main() returns 0 and the runtime tears down (teardown abort in MnkInputDriver - secondary).
  main = sub_82100000: if init sub_82100698 fails it shows 300 blank frames and quits. Init fails in
  its first subsystem (sub_8218D510 -> boot state machine sub_82178480, stage 0): the asynchronous
  load of st_pack_boot_pt_x360.afs (sub_823E24F0 -> CRI loader sub_82469320 / status sub_82469150,
  4 = error) - the 2 KiB header it reads is all zeros. Same on the Windows desktop build
  (tools/desktop/build_windows.sh) and with --no-crt, so not an SDK / ARM / rexcrt problem.
- **Root cause: the disc image under test was incomplete** (a truncated copy: only the first 1.78 GiB
  held data, the rest was zeros), so the pack headers read as zeros. Fixed by using a complete dump.
  Symptom worth remembering: ~5 s of black, then the game quits = init failure, check the CRI loads
  (--rb2_trace_loads) and your dump's file sizes (ANDROID.md lists them).
- Debug aids kept: --rb2_trace_loads (logs the CRI loads and their status), mkmanifest --no-crt /
  --no-file-crt, the desktop reference build.
- **rb2-a4 = rb2-best.apk: plays on the Thor.** Autosave notice -> logos -> intro -> title -> save
  creation works -> main menu -> Battle -> Single Battle (CPU vs CPU, no time limit) -> Goku vs Vegeta
  -> Wasteland. Menus and the intro run at 60.
- **Battle benchmark (CPU vs CPU, Wasteland, 60 s, bench.ps1):** 59.8 fps, p99 17.0 ms, 0.0 % frames
  > 18 ms; 376 draws/frame (max 543); GPU busy 11.8 ms/frame; GPU command processor 6.4 ms/frame;
  game process ~1.75 cores (Main XThread 42 %, GPU Commands 36 %, job threads 8-19 %);
  9.6 W, CPU 88-91 C / GPU 84-85 C (device already hot from the THP8 soak - re-measure cold).
  Heat is mostly GPU (70 % busy at the game's own 1280x720).
- Tools (tools/android/windows, live copies in C:\rb2-work\android\scripts): to_battle.ps1 (menu
  driver, screen recognition from runs\refs), bench.ps1 (fixed: `(ProcTicks - $k0)` is a PowerShell
  call with arguments - THP8's soak2.ps1 has the same bug, so its "CPU cores" were lifetime totals),
  step.ps1 (press + screenshot), try.ps1 (install + launch + exit/crash check), push_game.ps1.
- Next: GPU cost (render scale hook for the game's 1280x720 targets, post-processing), audio check,
  cold-device soak, controls hands-on by the owner.

## Session 2 (2026-10-11): missing music / dialogue

- Data ruled out: the sound pack's 43,457 entries all carry valid ADX headers (music = 62 stereo
  48 kHz tracks). The `sound/US/bgm/bgm_%02d_us.adx` / `sound/%s/character/cv_...`
  names in the logs are the game's logical stream names, not loose disc files.
- Tools: `--rb2_trace_cri` (logs messages passed to the CRI ADX / file-system error sinks; the
  string->callee map came from a decrypted image + scanning generated code for lis/addi pairs),
  SDK patch 0035 `--audio_dump_path=<file>` (per render client `<file>.N`, 6 planar BE float x 256
  per frame), `--audio_speaker_config`, scripts `audio_test.ps1` + `audio_levels.py`.
- Finding: the game registers TWO render clients. Client 0 carries everything; client 1 is silent
  the whole time. In client 0 the stereo title / menu music (bgm_05 / bgm_00) is a MONO fold (L+R,
  verified by correlating with the decoded ADX) on the 5.1 CENTER channel only - FL/FR exactly 0.
  The logo jingle is equal on FL/FR/C/BL/BR. Identical on the Windows desktop build -> not an ARM
  bug. Speaker config 0x00010001 / 1 / 0x00010000 change nothing.
- On the Thor the 6-channel stream lost the center channel -> no music. Fix (rb2-c6 = rb2-best):
  `--audio_force_stereo=true` (LaunchConfig default) opens a stereo device and folds 5.1 ourselves
  (center/surrounds at -3 dB). Still open: why the game mixes mono-to-center, what client 1 is for.
- Owner (rb2-c6): dialogue works, "music sounds good". Missing-audio report closed.
